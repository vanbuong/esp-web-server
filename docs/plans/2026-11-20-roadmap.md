# Gateway implementation roadmap

Spec: `docs/specs/2026-11-20-gateway-design.md`. The spec spans several subsystems, so it is built as
a sequence of plans. Each plan ends in firmware (or tooling) that works and is tested on its own.

| # | Plan | Delivers | Spec sections |
|---|---|---|---|
| 1 ✅ | `2026-11-20-p1-foundation-setup-mode.md` | Project skeleton, partitions, host tests, setup mode on esp32: SoftAP (fixed / per-device password), captive DNS, mDNS, login, forced password change, Wi-Fi scan + async test-connect, all via JSON API (curl-tested) | 5, 7.1, 7.1a, 7.2 (setup), 7.3 steps 1–3, 7.6, 7.7 |
| 2 | `2026-11-20-p2-tls-normal-mode.md` | `tools/pki` scripts, CSR + upload paths with validation, finish/reboot, HTTPS server, server-auth / mutual TLS Kconfig, SNTP, admin API | 7.3 steps 4–5, 7.4, 7.9, 7.10 |
| 3 | Svelte web UI | Svelte + Vite SPA (wizard + admin pages), LittleFS image, A/B `www` pairing + version check, build scripts | 7.5, 7.6 pairing |
| 4 | Device behaviour | Status LED (GPIO / RGB), BOOT long-press reset, normal-mode Wi-Fi change with pending/backup fallback, retry backoff | 7.2 (normal), 7.4 Wi-Fi change, 7.8 |
| 5 | Targets | Profiles esp32_psram, esp32s3, esp32s31, esp32p4 (+C6 spike first), TLS tuning per profile, `build_all.ps1`, product-security profile docs | 5, 7.7 product, 7.11 |

Each plan is written when the previous one is done, so it can build on what actually exists.
