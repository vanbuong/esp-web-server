# Firmware TDD (red → green → refactor)

Use together with `test-driven-development` (the general iron law); this adds the ESP-IDF specifics.
Adapted from obra/superpowers `test-driven-development` and mattpocock/skills `tdd` (MIT).

## Where tests live
- `test/host/` is an ESP-IDF app built for the `linux` target (`idf.py --preview set-target linux`).
  It runs the Unity tests of pure-logic components on the PC — fast, no board.
- Only components with no hardware includes can be host-tested. If logic you need to test is tangled
  with `esp_wifi`/`httpd`/GPIO, first split the pure part out (see CODING_STANDARDS "seams").
- Things that only exist on hardware (Wi-Fi connect, TLS handshake with a browser, mDNS on the LAN)
  are verified with a written hardware check, not faked tests.

## Before the first test
Agree the seam with the user when it's not obvious: which public function the test calls, and one
line on what the test will catch and what it won't.

## The loop — one behaviour at a time
1. **RED**: write one small test named for the behaviour
   (`test_cert_upload_rejects_key_not_matching_cert`). Use real inputs (real PEM fixtures from
   `test/host/fixtures/`, generated by `tools/pki`).
2. **Verify RED**: build and run. It must fail *for the expected reason* (missing behaviour, not a
   compile typo). A test that passes immediately tests nothing new — fix the test.
3. **GREEN**: simplest code that passes. Nothing extra.
4. **Verify GREEN**: that test passes and the whole host suite passes; firmware build of one profile still passes.
5. **REFACTOR** only while green; behaviour unchanged.

Bugs: first a failing test that reproduces the bug, then the fix.

## Don't
- Write all tests first, then all code (horizontal slicing). One slice per cycle.
- Assert on internals (static variables, call counts) — assert on outputs and returned `esp_err_t`.
- Recompute the expected value with the same logic as the code (tautological test).
- Keep code written before its test "as reference" — rewrite it through the loop.
- Skip the red step because "I already tested it manually".
